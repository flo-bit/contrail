Slim moderation, labels, Jetstream live ingest, Lexicon generation, and Alluvium bootstrap:

- **Moderation & labels:** Remove moderator `override` actions, `moderation_overrides`, `starts_at` delayed-expiry scheduling, `label_backfill_sources`, and `loadReportInboxes` from `@atmo-dev/contrail/moderation` (keeping report & action helpers). Simplify `reconcileModeratorActions` to a stateless bounded PDS diff/sync (up to 1,000 actions / 10 pages per moderator, warning loudly if truncated) and collapse `core/labels/` from 9 files to 3 (`index.ts`, `apply.ts`, `subscribe.ts`). If an existing database previously had active `moderation_overrides` rows, rebuild/backfill it so `moderation_hidden` reflects override removal.
- **Jetstream live ingest:** Remove the dead v1 `cursor_observations` table and per-commit `DELETE`, drop `getCursorObservations` / `save*CursorObservationStatements` / `cursorBoundaryDuplicatesDropped`, remove persistent-only feed sweep fields (`lastFeedSweepMs`, `lastFullFeedPassMs`, `feedDirty`) from `IngestState`, delete `core/runtime-telemetry.ts`, and share live-ingest session/account helpers between `jetstream.ts` and `persistent.ts`.
- **Lexicons & CLI (breaking CLI/API removals):** Remove `contrail lexicons all`, `contrail lexicons pull`, `contrail lexicons types`, `pullNsids`, `writeAtcuteConfig`, and the `contrail dev` auto-pull loop. Update scripts that ran `contrail lexicons all` to run `contrail lexicons generate` and `@atcute/lex-cli` (`lex-cli pull` / `lex-cli generate`) directly. `lex.config.js` is now user-managed (`--no-atcute-config` stays accepted as a no-op), `checkLexicons()` diffs in memory, `contrail dev` warns on missing source Lexicons, and `@atcute/lex-cli` + `@atcute/uint8array` are removed from runtime `dependencies`.
- **Alluvium & schema upgrades:** Remove the legacy pre-v0.32 `bootstrap_state` fallback and redundant legacy fingerprint hashes while preserving cheap upgrades from v0.24–v0.35 databases without rebuilding FTS, running Postgres `ALTER TABLE ... search_vector`, or reseeding `record_versions`. Existing databases refresh `moderation_effective_labels` cleanly; unused legacy tables (`cursor_observations`, `moderation_overrides`, `label_backfill_sources`) remain harmlessly on upgraded databases.
